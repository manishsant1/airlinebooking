# SkyBook

SkyBook, an airline booking portal: search daily flights by route and date, book seats for 1-9 passengers, and cancel up to 24 hours before departure. React + Vite frontend and a Node.js + Express API, run as **one process from one package**, with data stored in **Neon serverless Postgres**. Customers sign up with email and password to book. Demo only: no real payment is taken, and there is no email verification or password reset.

## Run

1. Create a Neon project at https://console.neon.tech and copy its connection string (Connect button).
2. Copy `.env.example` to `.env` and set `DATABASE_URL` to that string.
   Also set `BETTER_AUTH_SECRET` to a random string of 32+ characters: `node -p "require('crypto').randomBytes(32).toString('base64')"`.
3. Start the app:

```
npm install
npm run dev          # development: http://localhost:3000, with hot reload
```

On first start the server creates the tables and loads the starter data.

```
npm run build        # builds the frontend into dist/
npm start            # serves the API and the built app on http://localhost:3000
npm run smoke        # API checks against the running server (BASE_URL=... to target a deployment)
```

## Deploy (Render + Neon)

1. Push this folder to a GitHub repository (`.env` is git-ignored).
2. In Render choose **New > Blueprint**, pick the repository; `render.yaml` defines the service.
3. Set `DATABASE_URL` (your Neon connection string) when prompted. `BETTER_AUTH_SECRET` is generated by `render.yaml`.
4. After the first deploy: `BASE_URL=https://<your-service>.onrender.com npm run smoke`.

Any host that runs Node 22.9+ works: the build is `npm install --include=dev && npm run build` and the start command is `npm start`. The app keeps no data on local disk. Render's free plan sleeps after inactivity, so the first request after a pause is slow.

| Variable       | Default         | Purpose                          |
|----------------|-----------------|----------------------------------|
| `DATABASE_URL` | none (required) | Neon Postgres connection string  |
| `BETTER_AUTH_SECRET` | none (required) | Signs session cookies, 32+ chars; differs per environment |
| `BETTER_AUTH_URL` | `RENDER_EXTERNAL_URL`, else `http://localhost:PORT` | Public https address; set it on hosts other than Render or with a custom domain |
| `PORT`         | `3000`          | HTTP port (set by most hosts)    |

## How it fits together

```
server/
  index.js    Entry point. API at /api; dev: Vite inside Express; prod: serves dist/
  dev.js      Dev runner: restarts index.js when server/ or shared/ code changes
  routes.js   API endpoints and request validation
  auth.js     Better Auth setup (email + password, sessions in Postgres)
  db.js       All SQL: schema, queries, the booking transaction
  seed.js     Starter airports and flights, loaded into an empty database
shared/       Rules used by both browser and server (config, booking, validation)
src/
  api/api.js  The only place the frontend calls the server
  api/auth.js Better Auth client: useSession, signIn, signUp, signOut
  pages/      Home (search), Login, Book (passengers + contact), Bookings
```

### Data

`flights` are daily schedule entries (departure time in the origin airport's timezone, real elapsed duration, fare, seat count). `bookings` claim seats on one flight date and snapshot the route, times and prices so later schedule changes don't rewrite history. Fares are per passenger; a 12% tax/fees rate is added (`shared/config.js`).

### API

| Method | Path                                | Notes                                              |
|--------|-------------------------------------|----------------------------------------------------|
| GET    | `/api/health`                       | Health check                                       |
| GET    | `/api/airports`                     | Airports served                                    |
| GET    | `/api/flights?date=YYYY-MM-DD[&from=JFK&to=LAX]` | Flights with departure/arrival instants and `seatsLeft` |
| GET    | `/api/flights/:id?date=YYYY-MM-DD`  | One flight on a date; 404 if not found             |
| GET    | `/api/bookings`                     | The signed-in user's bookings; 401 if signed out   |
| POST   | `/api/bookings`                     | Signed in. `{ flightId, date, passengers: [{fullName}], contact: {email, phone} }` |
| POST   | `/api/bookings/:id/cancel`          | Owner only (others get 404); not within 24 hours of departure       |

Overselling is prevented by locking the flight row and counting confirmed passengers in the same transaction, so two requests racing for the last seats cannot both win (the loser gets a 409). Fares come from the database, never from the browser. Booking closes 2 hours before departure.

### Accounts

Better Auth (`server/auth.js`) handles sign-up, sign-in and sign-out under `/api/auth/*` with an httpOnly session cookie. Browsing and searching are public; booking and "My bookings" need an account (`requireUser` in `server/routes.js`, `RequireAuth` in the frontend). Bookings are scoped by `bookings.user_id`, and a user can hold at most 10 upcoming bookings. Better Auth's tables are `airline_user`, `airline_session`, `airline_account` and `airline_verification`, created on start. Bookings made before accounts existed (keyed by the old anonymous `client_id`) stay in the table but belong to no account.

To reset the data, drop the tables in the Neon SQL editor and restart (the server recreates and reseeds them):

```sql
DROP TABLE bookings, flights;
```
